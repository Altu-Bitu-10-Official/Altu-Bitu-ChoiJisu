### 📚 Tree(트리)
#### 1. 개념
트리는 **정점과 간선으로 이루어진 자료구조 중, 사이클이 없고 모든 정점이 연결되어 있는 그래프**이다.
루트를 정하면 부모-자식 관계가 생기고, 임의의 두 정점 사이의 경로가 항상 유일하다는 성질을 가진다.
그래프 문제 중 "간선 수 = 정점 수 - 1"이면서 사이클이 없는 경우를 트리라고 판별할 수 있다.

#### 2. 동작 원리 — 트리의 표현과 순회
트리는 `map<char, pair<char,char>>`처럼 각 노드가 자식(왼쪽/오른쪽)을 가리키는 형태로 표현할 수 있다.
전위(루트-왼-오), 중위(왼-루트-오), 후위(왼-오-루트) 순회는 **재귀적으로 왼쪽 서브트리 → 오른쪽 서브트리를 먼저 처리한 뒤, 루트를 언제 방문하느냐**의 차이일 뿐이다.
```cpp
void preorder(char v) {
    if (v == '.') return;
    ans += v;
    preorder(tree[v].first);
    preorder(tree[v].second);
}
void postorder(char v) {
    if (v == '.') return;
    postorder(tree[v].first);
    postorder(tree[v].second);
    ans += v;
}
```
> `1991_tree_map.cpp`(트리 순회)에서 직접 구현해봄. 노드를 문자로 받아 `map`에 왼쪽/오른쪽 자식을 저장한 뒤 세 가지 순회를 각각 재귀로 구현했다.

#### 3. 서브트리 크기 계산 — 자식에서 부모로 합산
어떤 정점을 루트로 하는 서브트리의 크기는 **자기 자신(1) + 모든 자식 서브트리 크기의 합**이다.
재귀로 자식을 먼저 계산한 뒤 부모에 더해 올라가는 방식인데, 정점 수가 많으면(10만개) 재귀 깊이 때문에 스택오버플로우 위험이 있어 BFS로 방문 순서를 먼저 구하고 그 역순으로 처리했다.
```cpp
// BFS로 부모와 방문 순서를 먼저 기록
// 이후 방문 역순으로 자식 크기를 부모에 더함
for (int i = (int)order.size() - 1; i >= 0; i--) {
    int cur = order[i];
    if (cur != r) size[parent[cur]] += size[cur];
}
```
> `15681_subtree_size.cpp`(트리와 쿼리)에서 구현해봄. 재귀 대신 BFS 역순 처리로 바꿔서 정점 10만 개짜리 편향 트리에서도 안전하게 동작하도록 했다.

#### 4. 트리 판별 — 사이클 탐지
그래프가 트리인지 확인하려면, DFS로 탐색하면서 **이미 방문한 정점을 (부모가 아닌데) 다시 방문하면 사이클**로 판단한다.
사이클이 없고 모든 정점이 하나로 연결되어 있으면 트리, 여러 조각으로 나뉘어 있으면 숲(forest)이다.
```cpp
void dfs(bool &flag, int cur, int prev, vector<vector<int>> &graph, vector<bool> &visited) {
    if (visited[cur]) { // 사이클 있음
        flag = false;
        return;
    }
    visited[cur] = true;
    for (int next : graph[cur]) {
        if (next == prev) continue;
        dfs(flag, next, cur, graph, visited);
    }
}
```
> `4803_treeCnt`(트리)에서 참고함. 방문하지 않은 정점마다 DFS를 새로 돌려서, 사이클 없이 끝까지 탐색되면 트리 개수를 하나씩 셌다.

#### 5. 전위 순회만으로 트리 복원 (범위 기반 재귀)
이진 검색 트리는 "왼쪽 서브트리 < 루트 < 오른쪽 서브트리" 성질 때문에, 전위 순회 배열만 있어도 트리를 다시 만들 수 있다.
트리를 실제로 만들지 않고, 배열을 **(하한, 상한) 범위**로 잘라가며 재귀하면 각 원소를 한 번씩만 소비하므로 O(N)에 해결된다.
```cpp
void build(int lo, int hi) {
    if (idx == n) return;
    int val = arr[idx];
    if (val < lo || val > hi) return; // 범위를 벗어나면 이 서브트리는 끝
    idx++;
    build(lo, val);   // 왼쪽 서브트리
    build(val, hi);   // 오른쪽 서브트리
    cout << val << "\n"; // 왼-오-루트 순서로 출력
}
```
> `5639_bst_postorder.cpp`(이진 검색 트리)에서 구현해봄. 트리를 별도로 구성하지 않고도 전위 순회 결과만으로 후위 순회 결과를 O(N)에 뽑아냈다.

#### 6. 트리 문제의 핵심 포인트
* 정점 수가 큰 경우(수만~십만) **재귀 깊이**를 항상 신경 써야 한다 — 편향 트리는 최악의 경우 선형 깊이가 되므로 BFS/스택 기반으로 바꾸는 게 안전하다.
* "자식을 먼저 처리하고 그 결과를 부모가 이용한다"는 패턴(서브트리 크기, 후위 순회)이 트리 문제 전반에 반복된다.
* 정렬된 성질(BST)을 이용하면, 트리를 실제로 구성하지 않고도 배열의 범위만으로 트리 구조를 유추할 수 있다.

#### 7. 느낀 점
트리 문제는 결국 "**자식의 결과를 어떻게 부모로 끌어올리느냐**"의 문제라는 걸 체감했다. 순회, 서브트리 크기, 트리 복원 모두 같은 재귀 구조(왼쪽 처리 → 오른쪽 처리 → 현재 노드 처리/결합) 위에서 무엇을 계산하느냐만 달랐다. 특히 BST 복원 문제에서 트리를 실제로 만들지 않고도 범위 재귀만으로 O(N)에 풀 수 있다는 점이 인상 깊었고, 정점 수가 커질 때는 재귀보다 BFS 기반 처리가 더 안전하다는 것도 다시 확인했다.
