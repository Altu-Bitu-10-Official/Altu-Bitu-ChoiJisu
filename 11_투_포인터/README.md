### 📚 Two Pointer(투 포인터)
###      Sliding Window(슬라이딩 윈도우)

#### 1. 개념

투 포인터는 **두 개의 포인터(인덱스)를 이용해 배열이나 리스트를 탐색하는 알고리즘**이다.
두 포인터를 적절히 이동시키며 원하는 조건을 만족하는 구간이나 값을 찾는다.
완전 탐색(`O(N²)`)으로 풀어야 할 문제를 **O(N)**으로 줄일 수 있는 경우가 많다.

#### 2. 동작 원리 — 양 끝에서 좁혀가는 방식

정렬된 배열에서 양 끝(`left`, `right`)을 이동시키며 조건을 만족하는 쌍을 찾는 방식이다.

```cpp
while (left < right) {
    int sum = arr[left] + arr[right];

    if (sum == target) {
        // 조건 만족
    } else if (sum > target) {
        right--; // 합이 크면 오른쪽 포인터를 왼쪽으로
    } else {
        left++;  // 합이 작으면 왼쪽 포인터를 오른쪽으로
    }
}
```

> `2470_mixSum.cpp`(두 용액)에서 직접 구현해봄. 배열을 정렬한 뒤, 합이 0에 가장 가까운 두 값을 양 끝에서 좁혀가며 찾았다.

#### 3. 동작 원리 — 슬라이딩 윈도우(Sliding Window)

고정되거나 가변적인 크기의 구간(윈도우)을 한 칸씩 이동시키며 탐색하는 방식이다.
매번 구간의 합/개수를 처음부터 다시 계산하지 않고, **빠지는 값을 빼고 들어오는 값만 더해서** 갱신하는 것이 핵심이다.

```cpp
// 초기 윈도우 설정
for (int i = 0; i < windowSize; i++) {
    cnt += arr[i];
}

// 한 칸씩 이동하며 갱신
for (int i = windowSize; i < n; i++) {
    cnt -= arr[i - windowSize]; // 윈도우에서 빠지는 값
    cnt += arr[i];              // 윈도우에 들어오는 값
}
```

> `21921_slidingWindow.cpp`(블로그)에서 고정 크기 윈도우로 구현해봄.

#### 4. 가변 크기 윈도우 (조건에 따라 늘리고 줄이기)

윈도우 크기가 고정되어 있지 않고, **조건을 만족하는 한 최대한 늘리다가 조건이 깨지면 좁히는** 방식이다.
`right`를 늘려가며 원소를 추가하고, 조건이 깨지면 `left`를 전진시켜 복구한다.

```cpp
int left = 0, ans = 0;

for (int right = 0; right < n; right++) {
    // 원소 추가
    cnt[a[right]]++;

    // 조건이 깨지면 left를 전진시켜 복구
    while (조건이 깨짐) {
        cnt[a[left]]--;
        left++;
    }

    // 유효한 윈도우 길이로 답 갱신
    ans = max(ans, right - left + 1);
}
```

> `20922.cpp`(겹치는 건 싫어)에서 직접 구현해봄. 같은 수가 K개를 초과하면 `left`를 옮겨 윈도우를 줄였다.

원형 배열(회전)에서도 같은 원리가 적용된다. `2531.cpp`(회전 초밥)에서는 `(s + k - 1) % N`처럼 나머지 연산으로 원형 인덱스를 표현하고, 윈도우가 한 칸 이동할 때 **빠지는 원소 처리 → 들어오는 원소 처리** 순서로 종류의 개수(`kinds`)를 갱신했다.

#### 5. 투 포인터의 핵심 포인트

* 배열이 **정렬되어 있어야** 유리한 경우가 많다 (양 끝 좁히기 방식의 경우 필수).
* 윈도우/구간이 이동할 때 **이전 결과를 재사용**해서 매번 처음부터 다시 계산하지 않는 것이 핵심.
* "원소를 추가/제거했을 때 상태가 어떻게 바뀌는가"를 자료구조(배열, 카운트 배열 등)로 관리하면 구현이 쉬워진다.

#### 6. 느낀 점

투 포인터는 배열을 두 번 순회하지 않고 **포인터를 영리하게 움직여 한 번의 순회로 답을 구할 수 있다**는 점이 핵심이었다. 특히 슬라이딩 윈도우에서는 "전체를 다시 계산하지 않고 차이만 갱신한다"는 아이디어가 시간 복잡도를 줄이는 데 큰 역할을 한다는 것을 체감했다. 정렬 후 양 끝에서 좁혀가는 패턴과, 한쪽 끝만 움직이며 조건을 유지하는 패턴 두 가지를 구분해서 이해하는 게 중요했다.
